# 验收用例（cursor-tts）

| 项 | 内容 |
|---|---|
| 版本 | v1.3 |
| 状态 | P0/P1 验收基线 |
| 关联契约 | [MCP工具契约](../spec/MCP工具契约.md) v1.3+ |
| 关联接入 | [Cursor接入与配置说明](../guide/Cursor接入与配置说明.md) |

> 用法：每条用例勾选「通过 / 失败 / 阻塞 / 抽查复测」。  
> P0 发布以 **确定性必过集** 全绿为准；**行为抽查集** 允许有限失败并复测记录，不因单次模型波动卡死发布。

---

## 0. 用例分级

| 级别 | 含义 | 门禁 |
|------|------|------|
| **D（确定性）** | 工具/引擎行为可重复 | P0 必须全绿 |
| **B（行为抽查）** | 依赖 Agent 是否遵守 User Rule | 至少按提示词跑 1 轮；失败可复测 1–2 次；仍失败则记风险但不与 D 混为一谈 |
| **P1** | 服务拆分与可选能力 | P1 里程碑使用 |

## 2. P0 确定性必过集（D）

### 2.1 播报与停止

| 编号 | 场景 | 步骤 | 期望 | 结果 |
|------|------|------|------|------|
| AC-SPK-01 | 基本播报 | 调用 `speak`，`text=接入测试成功`，`category=progress` | 可听到中文；返回 JSON 含 `ok/code/queued/message`；`code=OK` | ☐ |
| AC-SPK-02 | 受理不阻塞 | 在较长文案（≤80 码点）上调用 speak，观察返回与出声时刻 | 工具先返回，声音可稍后出现 | ☐ |
| AC-STP-01 | 停止播放 | speak 后在发音过程中立刻 `stop` | 声音立即中断；`was_playing=true`，`cleared=true` | ☐ |
| AC-STP-02 | 空闲停止 | 无播放时 `stop` | `ok=true`，`code=NOT_PLAYING`，进程不崩 | ☐ |

### 2.2 校验与契约

| 编号 | 场景 | 步骤 | 期望 | 结果 |
|------|------|------|------|------|
| AC-VAL-01 | 空文本 | `text=""` 或仅空白 | **协议层拒参**或 `ok=false`+`code=INVALID_TEXT`；无播报；进程不崩 | ☐ |
| AC-VAL-02 | 超长文本 | `text` 的 Unicode 码点长度 > `max_chars`(80) | `ok=false`，`code=TEXT_TOO_LONG`；无播报 | ☐ |
| AC-VAL-03 | 非法 category | 传入不在枚举的 category（若能发出） | 参数错误或拒绝；进程不崩 | ☐ |
| AC-DED-01 | 短窗去重 | 5s 内两次相同 text+category | 第二次 `code=DEDUPED`，`ok=true`；不明显双重叠播 | ☐ |
| AC-INT-01 | 错误打断清队列 | 先 speak 长句并再排队 1～2 句，再 speak `category=error`（不传 interrupt） | 旧播放停止、队列清空；仅新错误句可听（默认 interrupt=true） | ☐ |
| AC-QUE-01 | 短队列 | 快速连续 5 次不同 progress（不 interrupt） | 不崩；**等待队列最多 3**（另加正在播 1）；溢出丢最旧；最新进展最终可听 | ☐ |

### 2.3 引擎降级

| 编号 | 场景 | 步骤 | 期望 | 结果 |
|------|------|------|------|------|
| AC-FB-01 | 主路径成功 | 网络正常，默认配置 speak | 能出声；**MCP stderr 日志**显示使用 `edge-tts`（不以响应 `engine` 字段为准） | ☐ |
| AC-FB-02 | 降级 SAPI | 断网或将 edge 超时调极低，fallback=true | 仍可出声；**stderr** 显示 `sapi`；进程不崩 | ☐ |
| AC-FB-03 | 双失败 | fallback=false 且 edge 不可用 | 受理后后台失败仅 **stderr**，或罕见同步 `ENGINE_FAILED`；进程不崩；无僵尸狂占资源 | ☐ |

### 2.4 开关

| 编号 | 场景 | 步骤 | 期望 | 结果 |
|------|------|------|------|------|
| AC-NEG-03 | 总开关 | `CURSOR_TTS_ENABLED=false` 后 speak | `code=DISABLED`；无声音 | ☐ |

## 3. P0 行为抽查集（B）

> 依赖模型遵守 User Rule，结果非完全确定。建议固定提示词；失败先复测再结论。

| 编号 | 场景 | 步骤 | 期望 | 结果 |
|------|------|------|------|------|
| AC-PRG-01 | 中间进展可听 | 使用本文 **第 6 节**提示词，≥3 个可感知步骤 | **在任务结束前**至少听到 1 次进展类播报 | ☐ |
| AC-PRG-02 | 报错可听 | 制造可预期失败（错误命令/缺文件） | 出现 error/阻塞类播报，而非沉默到结束 | ☐ |
| AC-PRG-03 | 非仅收尾 | 复查同一次多步骤任务的播报时间线 | 若有 summary，不得是唯一一次播报 | ☐ |
| AC-NEG-01 | 不朗读全文 | 请 Agent 写一段长说明 | 不应把长文整段传入 speak；无「念稿」式长播报 | ☐ |
| AC-NEG-02 | 细节不刷屏 | 任务含多次读文件 | 不应每个读文件都 speak | ☐ |

**行为抽查通过标准（P0）**：AC-PRG-01 在 ≤2 次复测内至少 1 次通过；其余 B 类记录结果，严重「只在结束才说 / 全文朗读」须修复 Rule 或记豁免。

## 6. 手工验收脚本（提示词）

可用于 AC-PRG-01：

```text
请完成一个小任务并按 User Rule 播报进展：
1) 在临时目录创建 demo_tts_ok.txt
2) 写入一行：hello-tts
3) 用终端读出该文件内容
每完成一步若属于实质进展，立即 speak 一句短中文；不要等全部结束才说。
```

验收后删除临时文件；临时验证脚本用后即删。
