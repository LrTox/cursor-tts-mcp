# Cursor Agent TTS 播报功能设计

| 项 | 内容 |
|---|---|
| 版本 | v0.4 |
| 状态 | 草案（已锁定方向；**与契约/架构冲突时以契约与架构为准**） |
| 主路径 | A → C（两阶段） |
| 策略 | 自研薄 MCP + 借鉴开源 TTS/Hook，不整仓 fork |

---

## 1. 背景与目标

### 1.1 背景

在 Cursor Agent 长时间执行任务时，用户往往不会盯着屏幕。需要通过本地语音播报，把**可感知进展、阻塞与决策点**及时告知用户，而不是等整段任务结束才听到一句总结。

### 1.2 目标

1. **进展可听**：执行过程中有实质进展即播报短句中文，不等整任务结束。
2. **可控可停**：支持立即停止当前/队列中的播报。
3. **本地优先**：P0 以 `edge-tts` 为主、`Windows SAPI` 为兜底，无付费云依赖。
4. **薄接入**：以自研 MCP 暴露能力，Agent 主动调用；不绑定「默认朗读全文」。

### 1.3 非目标（至少到 P1 结束不做）

- ElevenLabs / 付费云 TTS（可预留接口，不进 MVP）
- 完整语音输入闭环（Wispr / Handy 等）
- 自研神经 TTS 模型
- macOS Background Helper
- 默认开启「每条回复全文朗读」

---

## 2. 总体方案

### 2.1 锁定路径

```
P0（A）：薄 MCP（speak / stop）+ 本进程 TTS 引擎 + 进展触发规则
    ↓
P1（C）：抽出本地 TTS 小服务（进程内队列 + stop）+ Hook（调研后可选）
```

借鉴开源 TTS/Hook 的实现思路与协议形态，**不整仓 fork**，避免品牌债与维护成本。

### 2.2 架构示意

```
┌─────────────────────────────────────────┐
│ Cursor Agent                            │
│  - User Rule：进展/错误/决策时调用 speak │
│  - 工具调用：speak / stop               │
└─────────────────┬───────────────────────┘
                  │ MCP
┌─────────────────▼───────────────────────┐
│ TTS MCP Server（薄层）                  │
│  - speak(text, ...)                     │
│  - stop()                               │
└─────────────────┬───────────────────────┘
                  │
     ┌────────────┴────────────┐
     ▼                         ▼
 edge-tts（主）           Windows SAPI（兜底）
```

P1 将引擎与队列下沉为本地小服务，MCP 仅作客户端适配。

## 3. 核心设计：触发策略

> **原则：有实质进展就触发；任务结果/结论交付也必须触发；不要只打字不说话。**

### 3.1 触发判定

| 事件类型 | 是否播报 | 说明 | 示例文案 |
|---------|---------|------|---------|
| 完成可感知步骤 | **是** | 用户能听懂「推进了一截」 | 「依赖已安装」「接口改完了」 |
| 发现阻塞 / 报错 | **是** | 需尽快吸引注意力 | 「构建失败，缺少环境变量」 |
| 需要用户决策 / 确认 / 操作 | **是** | 避免干等 | 「有两套方案，请你选择」「请重连 MCP」 |
| 阶段性里程碑 | **是** | 多步骤任务的中间节点 | 「单元测试已通过，开始联调」 |
| 排查结论 | **是** | 原因说明 | 「原因找到了：漏调了 speak」 |
| **任务结果 / 结论交付** | **是（必说）** | 向用户交付结果或操作指引 | 「规则已更新」「联调通过」 |
| 纯中间细节 | **否** | 读文件、小改动、检索等 | — |
| 工具调用本身成功 | **否** | 避免「说了又说」噪声 | — |

正式细则见 `.cursor/rules/cursor-tts-speak.mdc`。

### 3.2 文案约束

- 语言：简体中文
- 长度：建议 ≤ 30；硬上限默认 80（按 Unicode 码点计数）
- 超限策略：**拒绝并返回错误**（不截断静默播放）；细则见 [MCP工具契约](../spec/MCP工具契约.md)
- 内容：只说结论/状态，不朗读代码、日志、长段落
- 频率：同一回合内避免连续刷屏；由队列 + 去重策略保障

### 3.3 Agent 行为约定

正式 User Rule 定稿见 [Cursor接入与配置说明](../guide/Cursor接入与配置说明.md) 第 5 节；本节不再维护平行草案。
### 3.4 与旧方案差异

| 项 | 旧（已废弃） | 新（本稿） |
|----|-------------|-----------|
| P0 主触发 | 「结束必须说一句中文摘要」 | 执行中按进展主动 `speak` |
| 进度/错误播报 | 写在 P1 | **前置到 P0** |
| 回合末摘要 / 任务结果 | 可选 | **必说**（可与中间进展并存，不得省略） |

## 4. 功能范围

### 4.1 P0（MVP）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| MCP `speak` | 合成并播放短句中文 | P0 |
| MCP `stop` | 立即停止当前播放（及清空短队列，若有） | P0 |
| 引擎主路径 | `edge-tts` | P0 |
| 引擎兜底 | Windows SAPI（edge 失败/不可用时） | P0 |
| 进展触发 | 依赖 User Rule（定稿见接入说明）+ Agent 主动调用 | P0 |
| 形态 | 单进程；**受理即返回**，后台合成/播放；短队列 | P0 |
| 配置 | edge/sapi **分音色**、语速、兜底开关等 | P0 |

### 4.2 P1

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 本地 TTS 小服务 | 独立进程；**进程内内存队列**（非落盘）；统一 stop | P1 |
| 队列策略 | FIFO；`interrupt`/`stop` 默认清空队列（见契约） | P1 |
| 可选 Hook | 依赖 Cursor Hooks 能力调研；**默认不做 / 默认关**；不进 P1 必做门禁 | P1 可选 |
| 保留 MCP `speak` | 仍用于进度/错误/决策的主动播报 | P1 |
| 观测（基础） | P0 即输出引擎名等到 stderr（见接入说明）；P1 再增强 category/失败原因等字段 | P0 + P1 |

### 4.3 明确不做（见 1.3）

## 5. MCP 工具设计

工具名、入参/出参 Schema、错误码、`interrupt` 清队列语义、受理即返回等 **一律以实现合同为准**，本文不再维护平行字段表或示例 JSON，避免与契约漂移。

→ **[MCP工具契约](../spec/MCP工具契约.md)**（`speak` / `stop`）

摘要（非合同）：

- `speak`：进展/错误/决策短句播报；校验通过后尽快返回，后台合成播放。
- `stop`：停止当前播放；默认清空待播队列。

## 6. TTS 引擎

### 6.1 主引擎：edge-tts

- 优点：音质较好、中文可用、无本地模型负担
- 风险：依赖网络；需处理超时与失败切换

### 6.2 兜底：Windows SAPI

- 优点：离线可用、延迟低
- 场景：edge 失败、超时、未安装依赖时

### 6.3 选择策略

```
speak(text) 受理返回后，后台：
  → try edge-tts（限时）
  → on failure → Windows SAPI（若 enabled）
  → both fail → 记日志（进程不崩；通常不再回调 Agent）
```

### 6.4 预留（不做实现）

- 云厂商 TTS Provider 接口位，P1 后按需接入；MVP 不实现。

## 7. 运行与配置

### 7.1 部署形态

- **P0**：随 Cursor MCP 配置启动的本地 **Python 3.11+** 进程（已锁定，不再二选一）
- **P1**：MCP 适配进程 + 本地 TTS Service（本机 `127.0.0.1`）

### 7.2 配置项（建议）

| 键 | 默认 | 说明 |
|----|------|------|
| `tts.enabled` | true | 总开关 |
| `tts.engine.primary` | edge-tts | 主引擎 |
| `tts.engine.fallback` | sapi | 兜底 |
| `tts.edge.voice` | zh-CN-XiaoxiaoNeural | edge 专用音色 |
| `tts.sapi.voice` | （系统默认） | SAPI 专用；勿填 Neural ID |
| `tts.rate` | 默认 | 语速（edge 用 `+0%` 格式） |
| `tts.max_chars` | 80 | 文案上限（Unicode 码点） |
| `tts.edge.timeout_ms` | 8000 | edge 超时 |

配置来源优先级：环境变量 > 可选 `config/local.yaml` > `config/default.yaml`。完整键名与日志约定见接入说明。

### 7.3 Cursor 侧接入

1. 在 MCP 设置中注册本服务。
2. 添加/更新 User Rule（见 3.3）。
3. 验证：Agent 执行多步骤任务时，中间步骤能听到进展播报；`stop` 可立即打断。

## 8. 交互流程

### 8.1 进展播报（主路径）

```
用户下达多步骤任务
  → Agent 完成步骤 A（可感知）
  → 调用 speak(category=progress, text="…")
  → 用户听到进展
  → Agent 继续步骤 B…
  → 出错 → speak(category=error, interrupt=true, text="…")
  → 用户可口头/文本介入，或调用 stop
```

### 8.2 停止

```
用户要求停止 / Agent 调 stop
  → 中断当前播放
  → 清空队列
  → 后续 speak 仍可再次受理（除非总开关关闭）
```

## 9. 验收标准

### 9.1 P0

- [ ] `speak` 能播放中文短句；`stop` 能立即停止。
- [ ] edge-tts 不可用时，自动落到 SAPI（在启用兜底下）。
- [ ] 多步骤任务中，**至少在中间进展点**出现播报，而非仅在任务结束。
- [ ] 纯读文件/小改动类步骤不强制播报（靠规则约束；抽查 Agent 行为）。
- [ ] 超长文本被拒绝（不截断播放），且 MCP 不崩溃。
- [ ] 不默认朗读 Agent 完整回复正文。

### 9.2 P1

- [ ] 本地服务支持队列与 stop 清空。
- [ ] Hook：调研可行时默认关闭且可开关；不可用则记 N/A。
- [ ] MCP `speak` 仍可用于进度/错误主动播报。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Agent 过度播报 | 吵、干扰 | 规则约束 + category/去重 + 文案上限 |
| Agent 只在结束才说 | 违背产品目标 | 验收明确要求「中间进展点」；规则措辞强调「立即」 |
| edge-tts 网络不稳 | 延迟/失败 | 超时 + SAPI 兜底 |
| 播放阻塞工具调用 | 拖慢 Agent | 提交播放后尽快返回；P1 队列化 |
| 与其它音频争用 | 体验差 | stop 能力；后续可加简单互斥 |
